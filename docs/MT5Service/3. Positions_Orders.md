# MT5Service — 3. Positions & Orders

> Open book, ticket lists and history — with typed sort enums and a scalar `positions_total`.

**Layer:** MID over [`MT5Account` Positions & Orders](../MT5Account/3.%20Positions_Orders/Positions_Orders.Overview.md). Defined in [`src/mt5/service.rs`](https://github.com/MetaRPC/RustMT5/blob/main/src/mt5/service.rs).

---

## The 5 methods

| Method | Returns | Tier | Delegates to |
|--------|---------|------|--------------|
| `positions_total()` | `i32` | 🟢 clean | `positions_total().total_positions` |
| `opened_orders(sort_mode)` | `OpenedOrdersData` | 🔵 friendly args | `opened_orders(..)` |
| `opened_orders_tickets()` | `OpenedOrdersTicketsData` | ⚪ pass-through | `opened_orders_tickets(default)` |
| `order_history(sort_mode, from, to, page, per_page)` | `OrdersHistoryData` | 🔵 friendly args | `order_history(..)` |
| `positions_history(sort_type, from, to, page, per_page)` | `PositionsHistoryData` | 🔵 friendly args | `positions_history(..)` |

**Where the value is:** `positions_total()` returns the bare `i32`; the others take a **typed sort enum** (and plain `Option<Timestamp>` ranges / paging) instead of a hand-built request. Payloads with many fields (`OpenedOrdersData`, histories) are returned as-is — see the low-level pages for the field tables.

## Signatures

```rust
pub async fn positions_total(&self) -> Result<i32, MT5Error>

pub async fn opened_orders(&self, sort_mode: pb::Bmt5EnumOpenedOrderSortType) -> Result<pb::OpenedOrdersData, MT5Error>

pub async fn order_history(
    &self,
    sort_mode: pb::Bmt5EnumOrderHistorySortType,
    from: Option<prost_types::Timestamp>,
    to: Option<prost_types::Timestamp>,
    page_number: i32,
    items_per_page: i32,

pub async fn positions_history(
    &self,
    sort_type: pb::AhEnumPositionsHistorySortType,
    from: Option<prost_types::Timestamp>,
    to: Option<prost_types::Timestamp>,
    page_number: Option<i32>,
    items_per_page: Option<i32>,
) -> Result<pb::PositionsHistoryData, MT5Error>
```

### Sort enums

* `Bmt5EnumOpenedOrderSortType`: `...SortByOpenTimeAsc`=0, `...Desc`=1, `...SortByOrderTicketIdAsc`=2, `...Desc`=3.
* `Bmt5EnumOrderHistorySortType`: open/close/ticket × asc/desc (0–5).
* `AhEnumPositionsHistorySortType`: `AhPositionOpenTimeAsc`=0, `...Desc`=1, `AhPositionTicketAsc`=2, `...Desc`=3.

> Field tables for `OpenedOrdersData` (`position_infos` + `opened_orders`), `OrdersHistoryData` and `PositionsHistoryData` live in the low-level [opened_orders](../MT5Account/3.%20Positions_Orders/opened_orders.md), [order_history](../MT5Account/3.%20Positions_Orders/order_history.md) and [positions_history](../MT5Account/3.%20Positions_Orders/positions_history.md) pages.

## 🔗 Usage Examples

### 1) Count + list open positions

```rust
use metarpc_mt5::proto::mt5_term_api as pb;
use pb::Bmt5EnumOpenedOrderSortType as Sort;

if service.positions_total().await? > 0 {
    let data = service.opened_orders(Sort::Bmt5OpenedOrderSortByOpenTimeAsc).await?;
    for p in &data.position_infos {
        println!("#{} {} {:.2} lot  P/L {:+.2}", p.ticket, p.symbol, p.volume, p.profit);
    }
}
```

### 2) Last 7 days of order history

```rust
use metarpc_mt5::proto::mt5_term_api as pb;
use pb::Bmt5EnumOrderHistorySortType as Sort;

fn ts(s: i64) -> prost_types::Timestamp { prost_types::Timestamp { seconds: s, nanos: 0 } }
let now = chrono::Utc::now().timestamp();

let h = service.order_history(Sort::Bmt5SortByCloseTimeDesc, Some(ts(now - 7*86_400)), Some(ts(now)), 0, 50).await?;
println!("{} rows", h.array_total);
```

### 3) Closed positions, net realized

```rust
use metarpc_mt5::proto::mt5_term_api as pb;
use pb::AhEnumPositionsHistorySortType as Sort;

fn ts(s: i64) -> prost_types::Timestamp { prost_types::Timestamp { seconds: s, nanos: 0 } }
let now = chrono::Utc::now().timestamp();

let data = service.positions_history(Sort::AhPositionOpenTimeDesc, Some(ts(now - 30*86_400)), Some(ts(now)), Some(0), Some(100)).await?;
let net: f64 = data.history_positions.iter().map(|p| p.profit + p.swap + p.commission + p.fee).sum();
println!("net realized (30d): {net:+.2}");
```

## ⚠️ Pitfalls

* **`order_history` paging is required `i32`** (`page_number`, `items_per_page`); `positions_history` uses `Option<i32>`.
* **Ranges are `Option<Timestamp>`** — build `prost_types::Timestamp { seconds, nanos }`.
* **`opened_orders_tickets` tickets are `i64`** (see the low-level note); the streaming variant uses `u64`.
