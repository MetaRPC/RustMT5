# MT5Service — 1. Account Information

> Account snapshot + single typed properties, returned as **clean scalars** (`f64`/`i64`/`String`) instead of protobuf `…Data`.

**Layer:** MID — friendly wrappers over [`MT5Account`](../MT5Account/1.%20Account_Information/Account_Information.Overview.md). Defined in [`src/mt5/service.rs`](https://github.com/MetaRPC/RustMT5/blob/main/src/mt5/service.rs).

---

## The 4 methods

| Method | Returns | Tier | Delegates to |
|--------|---------|------|--------------|
| `account_summary()` | `AccountSummaryData` | ⚪ pass-through | `account.account_summary()` |
| `account_double(property_id)` | `f64` | 🟢 clean | `account.account_info_double(..).requested_value` |
| `account_integer(property_id)` | `i64` | 🟢 clean | `account.account_info_integer(..).requested_value` |
| `account_string(property_id)` | `String` | 🟢 clean | `account.account_info_string(..).requested_value` |

**Where the value is:** the three `account_*` getters take a typed property enum and hand back the bare value — no `…Request` to build, no `.requested_value` to pull out. `account_summary()` is a straight pass-through (returns the same `AccountSummaryData` as the low-level call).

> Unlike the Python facade, this `account_summary()` does **not** fan out extra RPCs for margin/free-margin — read those with `account_double(AccountMargin…)`. See the low-level [account_summary](../MT5Account/1.%20Account_Information/account_summary.md) for the exact `AccountSummaryData` fields.

---

## Signatures

```rust
pub async fn account_summary(&self) -> Result<pb::AccountSummaryData, MT5Error>

pub async fn account_double(&self, property_id: pb::AccountInfoDoublePropertyType) -> Result<f64, MT5Error>
pub async fn account_integer(&self, property_id: pb::AccountInfoIntegerPropertyType) -> Result<i64, MT5Error>
pub async fn account_string(&self, property_id: pb::AccountInfoStringPropertyType) -> Result<String, MT5Error>
```

Note the argument is the **typed enum** (e.g. `AccountInfoDoublePropertyType::AccountBalance`), not an `i32` — the Service does the cast.

### Property enums (common values)

**`AccountInfoDoublePropertyType`:** `AccountBalance`=0, `AccountCredit`=1, `AccountProfit`=2, `AccountEquity`=3, `AccountMargin`=4, `AccountMarginFree`=5, `AccountMarginLevel`=6, … (see [account_info_double](../MT5Account/1.%20Account_Information/account_info_double.md) for the full 14).

**`AccountInfoIntegerPropertyType`:** `AccountLogin`=0, `AccountTradeMode`=1, `AccountLeverage`=2, `AccountTradeAllowed`=5, `AccountTradeExpert`=6, … (11 total).

**`AccountInfoStringPropertyType`:** `AccountName`=0, `AccountServer`=1, `AccountCurrency`=2, `AccountCompany`=3.

## 🔗 Usage Examples

### 1) Read single properties as scalars

```rust
use metarpc_mt5::proto::mt5_term_api as pb;
use pb::{AccountInfoDoublePropertyType as D, AccountInfoIntegerPropertyType as I, AccountInfoStringPropertyType as S};

let balance  = service.account_double(D::AccountBalance).await?;      // f64
let free     = service.account_double(D::AccountMarginFree).await?;   // f64
let leverage = service.account_integer(I::AccountLeverage).await?;    // i64
let currency = service.account_string(S::AccountCurrency).await?;     // String

println!("{balance:.2} {currency}  free {free:.2}  1:{leverage}");
```

### 2) Account banner from the summary

```rust
let s = service.account_summary().await?;
println!("#{}  {}  equity {:.2} {}", s.account_login, s.account_company_name, s.account_equity, s.account_currency);
```

### 3) Margin picture (fields not in the summary)

```rust
use metarpc_mt5::proto::mt5_term_api::AccountInfoDoublePropertyType as D;

let margin = service.account_double(D::AccountMargin).await?;
let level  = service.account_double(D::AccountMarginLevel).await?;  // percent
println!("margin {margin:.2}, level {level:.1}%");
```

---

## ⚠️ Pitfalls

* **Typed enum, not `i32`.** Pass `D::AccountBalance`, not `0` — the Service casts internally.
* **No margin in the summary.** Use `account_double(AccountMargin/…MarginFree/…MarginLevel)`.
* **Margin level is a percent.**
